# FCK Famous Group — каталог мерчу

Одностраничный каталог: React + TypeScript (Vinext), Cloudflare Workers и база SQLite / D1. Шапка и нижняя панель закреплены, центральная часть прокручивается. Разделы используют hash-навигацию и поддерживают Back/Forward.

## Локальный запуск, в том числе из PyCharm

Откройте папку `store` в PyCharm и выполните в его терминале (Node.js 22.13+):

```sh
npm ci
npx wrangler d1 migrations apply DB --local
npm run dev
```

Эту команду используйте для новой базы. Для существующей базы, где миграции выполнялись вручную, сначала нужна резервная копия и сверка журнала миграций. Откройте адрес, который выведет терминал, обычно http://localhost:3000. Сервер останавливается через Ctrl+C. Локальная БД хранится в `.wrangler/` и не отправляется в Git.

```sh
npx tsc --noEmit
npm run build
```

## Заказы и ссылки

Корзина и оформление заказа отключены. Покупатель выбирает модель и размер, затем пишет менеджеру в Instagram или Telegram. Ссылки сервисов и профилей для заказа находятся в `lib/links.ts`; для заказа используются отдельные профили менеджера fckfamous.shop и fckfamousshop. Сообщения не отправляются автоматически, сайт не собирает имя или телефон.

`POST /api/orders`, `POST /api/internal/notifications` и `POST /api/internal/cancel` возвращают HTTP 410 независимо от старых переменных окружения. Старые таблицы и история заказов сохранены; новый интерфейс ими не пользуется. Заказ во внешнем мессенджере не уменьшает остаток автоматически: менеджер обновляет его вручную.

## Каталог

Каталог содержит модели мерча и стикеры; цены и наличие заполняются в админке. Настоящие товары хранятся в таблице `products`: `id` — primary key, `title` — название, `quantity` — остаток. Дополнительные поля: `slug`, `size`, `price` (целые гривны), `subtitle`, `description`, `image`, `category`, `active`. Размеры представлены отдельными строками.

Демо-товары архивированы. Управляйте настоящим каталогом через `/dima_dinamo_admin`. Не редактируйте уже применённые миграции.

## Музыка и оформление

Музыкальные треки находятся в `public/audio/`, список — в `components/music-player.tsx`. Плеер сохраняет паузу и громкость, переключает треки по окончании и продолжает играть при переходах между разделами. Браузер может блокировать автозапуск со звуком; тогда посетитель нажимает кнопку Play. Интерфейс адаптируется к мобильному и настольному экрану.

Иконки сервисов находятся в `public/icons/`, сведения об источнике — в `NOTICE.txt` в той же папке.

## Панель, языки и фотографии

Руководство владельца — [OWNER_GUIDE.md](OWNER_GUIDE.md). Витрина поддерживает UKR / ENG, панель — на украинском с отдельными полями для обоих языков. Новые переводы хранятся в `products.title_en`, `subtitle_en`, `description_en`. Исчезнувший перевод старого товара отображается на украинском, новые карточки требуют оба названия и описания.

Фотографии загружаются в R2 (`MEDIA`) и отдаются `/api/media/[key]`. При повторной публикации ни R2, ни D1 не заменяются каталогом файлов. Неиспользованные загруженные фото автоматически не удаляются. Админ-панель не поддерживает массовый импорт или галереи нескольких фотографий одного товара.

Веб-регистрация отключена. Единственный логин задаётся секретом `ADMIN_LOGIN`, существующий пароль сохраняется. Для новой установки запустите `node scripts/prepare-admin.mjs` в терминале: он запросит логин, серверный секрет и пароль без отображения, создаст игнорируемый `.sites-runtime/admin-initial.env`. Значения `ADMIN_LOGIN`, `ADMIN_SECRET`, `ADMIN_INITIAL_CREDENTIAL` внесите в секреты хостинга и выполните публикацию. Для новой локальной установки: `node scripts/prepare-admin.mjs --local`, затем перезапуск сервера. После первого успешного входа удалите `ADMIN_INITIAL_CREDENTIAL` из секретов и локальный файл подготовки: повторное создание учётной записи через сайт отсутствует. Существующий `ADMIN_SECRET` никогда не заменяйте: он защищает пароль и TOTP. Скрипт не сбрасывает существующий пароль.

Все операции изменения требуют активной серверной сессии и совпадающего Origin. На HTTPS cookie имеет Secure, HttpOnly и SameSite=Strict. Вход и загрузки ограничены по частоте. Сохранение всех вариантов происходит атомарно; ревизия каталога предотвращает перезапись параллельным редактором. Удаление размера архивирует строку и сохраняет ссылки исторических заказов.

## Проверка изменений и запуск

`npx tsc --noEmit`, `npm audit --audit-level=moderate`, `npm run security:history` и `npm run build`. После сборки выполните `node scripts/test-security.mjs`: он создаёт отдельную временную D1/R2 в игнорируемой папке, использует порт 3011 и проверяет именно production-сборку. Рабочая локальная база и пароль не используются. Порт 3011 должен быть свободен. Тест проверяет авторизацию, MFA и резервные коды, CSRF, загрузку фото, товарные операции, конфликты, смену пароля, отзыв/простой сессии и миграцию старого хеша пароля.

Для существующей базы не запускайте повторно старые SQL-файлы: применяйте только новые миграции после резервной копии. Не публикуйте dev-сервер в Интернет.

Шаблон настроек: [.env.sample](.env.sample). Не копируйте его поверх существующего `.dev.vars`.
