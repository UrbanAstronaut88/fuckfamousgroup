# Безопасность и подготовка к запуску

Панель находится по `/dima_dinamo_admin`. Секретность URL не является механизмом авторизации: исходники сайта могут быть публичными, а доступ к данным всё равно должен требовать проверки на сервере. В этой версии один администратор; отдельных сотрудников, ролей и журнала действий пользователей нет.

## Что защищает панель

- Пароль: PBKDF2-SHA256, 600 000 итераций, случайная соль и отдельный серверный HMAC-секрет. Старый пароль с 100 000 итераций обновляется при успешном входе без сброса.
- На HTTPS второй фактор обязателен до доступа к каталогу и загрузкам. TOTP работает с Google/Microsoft Authenticator и другими совместимыми приложениями. На localhost его можно сделать обязательным через `ADMIN_REQUIRE_MFA=true`.
- Ключ TOTP хранится в D1 с шифрованием AES-GCM; ключ шифрования выводится из `ADMIN_SECRET`. Восемь резервных кодов показываются один раз, хранятся как хеши и используются по одному. Повторное использование кода TOTP в том же временном окне запрещено.
- Cookie на HTTPS: `__Host-ffg_admin`, Secure, HttpOnly, SameSite=Strict, без Domain. В базе хранится только хеш случайного токена. Сессия истекает через 8 часов или 30 минут бездействия; смена пароля/автентификатора отзывает старые сессии.
- Проверка Origin и HTTPS для изменений, ограниченный размер запросов, лимиты попыток входа и загрузок, проверки всех операций на сервере. Загружаются только JPEG/PNG/WebP до 8 МБ и 40 МП.
- Защитные HTTP-заголовки, запрет встраивания страниц в iframe и кеширования панели. CSP пока разрешает inline-скрипты для потоковой загрузки React; она не является полной защитой от XSS. HTML из описаний товаров не исполняется.
- Старые endpoints заказов, уведомлений и отмены отключены (410). Данные прежних заказов сохранены, но не доступны через эти endpoints.

## Перед отправкой на GitHub

Из корня репозитория один раз выполните `git config core.hooksPath .githooks`. На этом компьютере уже настроено. Затем из `store`:

```sh
npm run security:history
npm audit --audit-level=moderate
npx tsc --noEmit
npm run build
node scripts/test-security.mjs
```

Сканер проверяет рабочие файлы, Git index, доступную локально историю, известные локальные секреты и распространённые форматы ключей. Он не заменяет GitHub secret scanning и не гарантирует обнаружение произвольного секрета. Старые файлы `.idea` в истории отмечаются предупреждением; наличие секрета в любом проверенном текстовом файле блокирует проверку. История автоматически не переписывается.

В `.gitignore` исключены `.env*`, `.dev.vars*`, `.sites-runtime`, `.wrangler`, базы, архивы, приватные ключи, настройки IDE, зависимости и сборки. Не используйте `git add -f` для этих файлов. Сканер перед коммитом проверяет именно подготовленные к коммиту файлы. GitHub Actions повторяет проверки без production-секретов; Dependabot предлагает обновления. В репозитории GitHub отдельно включите доступные вашему тарифу secret scanning / push protection и защиту основной ветки с обязательной проверкой CI.

Сборка удаляет копии `.dev.vars`/`.env`, которые может создать Cloudflare plugin, и проверяет результат. Публиковать следует только проверенный `dist`, без локальных файлов. Удаление секретов из исходников само по себе недостаточно, если они уже попали в историю или архив: такой секрет нужно отозвать и заменить.

## Секреты и резервные копии

Веб-регистрация отключена. Единственный логин задаётся секретом `ADMIN_LOGIN`, существующий пароль сохраняется. Для новой установки запустите `node scripts/prepare-admin.mjs` в терминале: он запросит логин, серверный секрет и пароль без отображения, создаст игнорируемый `.sites-runtime/admin-initial.env`. Значения `ADMIN_LOGIN`, `ADMIN_SECRET`, `ADMIN_INITIAL_CREDENTIAL` внесите в секреты хостинга и выполните публикацию. Для новой локальной установки: `node scripts/prepare-admin.mjs --local`, затем перезапуск сервера. После первого успешного входа удалите `ADMIN_INITIAL_CREDENTIAL` из секретов и локальный файл подготовки: повторное создание учётной записи через сайт отсутствует. Существующий `ADMIN_SECRET` никогда не заменяйте: он защищает пароль и TOTP. Скрипт не сбрасывает существующий пароль.

Не меняйте `ADMIN_SECRET` произвольно: он нужен для проверки пароля и расшифровки TOTP. Храните резервную копию в менеджере паролей отдельно от базы. Сохраните пароль и резервные коды второго фактора. Замена автентификатора требует активной сессии и текущего пароля; при потере телефона можно войти по резервному коду и подключить новый телефон. Восстановление при потере всех факторов возможно только через владельца инфраструктуры; публичного endpoint для обхода MFA нет.

Перед миграцией сделайте закрытую резервную копию D1 и файлов R2. Настройте регулярные копии и проверьте восстановление в отдельной среде. В бэкапах могут быть хеши доступа, зашифрованный TOTP и исторические данные заказов — не добавляйте их в Git или публичное хранилище. Для Cloudflare D1 доступность и срок Time Travel зависят от тарифа: проверьте их в аккаунте. Фото R2 резервируются отдельно.

## Что ещё требуется на хостинге перед публичным запуском

1. Подключить `fckfamous.group`, проверить HTTPS, домен и доступность публичной витрины. Локальный `npm run dev` не является production-хостингом.
2. Применить миграции к правильной базе без повторного выполнения уже применённых SQL. Для существующей локальной базы этого проекта новая миграция — `drizzle/0003_round_omega_red.sql`; она добавляет поля сессии и не меняет товары или пароль. Старые сессии завершатся.
3. Активировать панель на production, подключить MFA, сохранить резервные коды и убрать секрет первичной активации. Включить MFA также у аккаунтов GitHub, хостинга и регистратора домена.
4. Проверить лимиты CPU/запросов хостинга: хеширование паролей намеренно затратное. Проверить ошибки, алерты и лимиты расходов. Edge/WAF-защита может дополнять лимит входа по IP; приложение не заменяет защиту от распределённых атак. Не сохранять пароли, cookie, коды MFA и тела запросов входа в логах.
5. При необходимости поставить Cloudflare Access или другой шлюз перед **обоими** `/dima_dinamo_admin*` и `/api/dima_dinamo_admin*`. Одного ограничения страницы недостаточно. Настройка зависит от доступа к хостингу/DNS и не включена автоматически этим кодом.
6. Проверить восстановление резервной копии, вход, добавление/скрытие товара, фотографии и оба языка на целевом домене.

Vinext используется в beta-версии. Обновления и локальные проверки уменьшают риск, но не делают проект сертифицированным или полностью защищённым. Для запуска с высокой критичностью требуется отдельно оценить beta-runtime, инфраструктуру, нагрузку и независимый аудит.

Ориентиры: [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html), [Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [MFA](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html).
