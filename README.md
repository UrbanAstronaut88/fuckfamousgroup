# FCK Famous Group

Репозиторий сайта мерча. Само приложение находится в папке `store`.

## Структура

```text
.github/            Проверки GitHub Actions и обновления зависимостей
.githooks/          Проверка секретов перед коммитом
.gitignore          Общие исключения для GitHub-репозитория
store/
  .gitignore        Исключения приложения, включая отдельную публикацию
  app/              Страницы витрины, админка и API
  components/       Общие компоненты интерфейса
  lib/              Каталог, авторизация, переводы и настройки
  db/               Схема базы и подключение
  drizzle/          SQL-миграции базы
  public/           Статические изображения, иконки и музыка
  scripts/          Сборка, проверка секретов и проверки безопасности
  tests/            Автоматические проверки
  .openai/          Конфигурация размещения Sites
```

Два `.gitignore` намеренны: правила корневого файла действуют на весь репозиторий, а правила `store/.gitignore` сохраняют защиту при отдельной публикации приложения. Это не две копии сайта.

## Работа локально

Команды npm запускаются из `store`:

```sh
cd store
npm ci
npm run dev
```

При первом запуске также нужна настройка локальной базы и секретов: см. [инструкцию приложения](store/README.md) и [руководство владельца](store/OWNER_GUIDE.md).

Чтобы включить локальную проверку перед коммитом после клонирования, выполните из корня репозитория:

```sh
git config core.hooksPath .githooks
```

## Данные и публикация

- `.dev.vars` и `.env*` содержат локальные настройки и не должны попадать в Git. `.env.sample` и `.env.example` — только шаблоны без настоящих секретов.
- `store/.wrangler/` содержит локальные данные D1/R2, включая каталог и загруженные фотографии. Не удаляйте эту папку при уборке проекта.
- `store/.sites-runtime/` содержит служебные локальные файлы, резервные копии и данные публикации. Она исключена из Git.
- `node_modules/`, `dist/`, `.next/` и `.vinext/` — зависимости и результаты работы инструментов, также исключённые из Git.
- Миграции, исходники, `package-lock.json` и статические файлы из `public/` должны храниться в Git.

Локальная и размещённая базы — разные. Публикация кода не переносит товары и загруженные фотографии с компьютера. Наполняйте каталог в админке целевого сайта либо отдельно планируйте перенос D1 и R2 с резервной копией. Повторная публикация кода сохраняет уже размещённый каталог.

Перед отправкой исходников выполните из `store`:

```sh
npm run security:history
```

Проверки перед выпуском, настройка секретов и резервные копии описаны в [SECURITY.md](store/SECURITY.md).

Пошаговый первый запуск: [DEPLOYMENT.md](DEPLOYMENT.md).
